    13_Train_Test › Train and test sets

    Where we are  ·  the honest test

    A model must be judged on data it never saw.

    • The size of the residuals is not a reliable guide to the size of the forecast errors. The model has seen the training data; it could have learned its noise as well as its signal.
    • The future does not exist yet, so hide the end of the series and let it stand in for the future. Fit on the rest, forecast the hidden part, compare.
    • Train to fit, test to judge. Every model comparison from here on, including Group Assignment 2, follows this split.

    Fitting well is cheap. Forecasting well is the only thing that counts, and only a test set can measure it.

    The test set is a rehearsal for the future: the model is given the past up to a point, asked to forecast, and then shown what happened. The difference between the forecast and what happened is the forecast error. Session 14 repeats the rehearsal many times.

    Nothing about the test set is special except that the model never touched it. If it leaks into the fit, through a transformation chosen on the whole series, for example, the test is no longer honest.
    13_A › Forecast errors vs residuals

    From benchmark methods (Session 8)  ·  now it earns its keep

    A residual is a one-step miss inside the data. A forecast error is a miss on the future you hid.

    Residual

    Observation minus fitted value, yt − ŷt|t−1, on the training set. Always one step ahead, because a fitted value is a one-step forecast made inside the data.

    Forecast error

    Observation minus forecast, yT+h − ŷT+h|T, on the test set. Any horizon h: the first hidden quarter is a one-step error, the tenth a ten-step error.

    • Two differences, and only two: where the comparison happens, training or test, and how far ahead the forecast reached, one step or h.
    • Error is not mistake. It is the unpredictable part of an observation: whatever the model could not capture. A good model still has errors; it has small, patternless ones.
    • Prediction intervals (Session 12) used residuals to set the width of the interval. This session uses forecast errors to judge the model. It is the same subtraction, applied to different data.

    The residuals show how the model did in rehearsal, on the training data, and the forecast errors show how it did on the test set.

    Why residuals are always one step ahead: a fitted value at time t is the model's forecast of yt from everything up to t minus 1. So the residual at t is a one-step miss by construction. Forecast errors on the test set are made from the end of the training set, T, and reach h steps out, so the tenth test observation is compared with a ten-step forecast.

    Multi-step errors are usually larger than one-step errors, for the same reason the prediction intervals of Session 12 widen with the horizon.

    Two practical questions

    Hold back about a fifth, and never trust a perfect training fit.

    • How much to hide: around 20% of the series, at least as long as the longest horizon you need, and ideally three times that. Hide too much and the training set is too short to learn from.
    • A perfect fit is a warning. With enough parameters any model threads every training point; it has memorized the noise, and the noise will not repeat on the test set. That is overfitting.
    • Overfitting is as bad as missing the pattern. Both forecast badly; one of them looks wonderful on the training set first.

    A good training fit shows that a model can learn from the data, but you need the test set to find out whether what it learned carries over to new observations.

    The 20% rule is a rule of thumb, not a law. The three requirements pull against each other: a longer test set judges more reliably, a longer training set estimates more reliably, and the test set has to reach at least as far as you intend to forecast. With a short series something has to give, and Session 14's cross-validation is the way to get more judging out of the same data.

    Session 18 returns to overfitting with the Holt–Winters models, which have many parameters: "with four parameters I can fit an elephant".
    13_Train_Test › Functions to subset a time series

    Now we compute

    Two verbs cut a series, and the parentheses decide which rows you get.

    # by condition aus_production |> filter(year(Quarter) >= 1995) # by position: everything but the last 12 rows of each series, then only those 12 aus_retail |> group_by(State, Industry) |> slice(1:(n() - 12)) |> ungroup() aus_retail |> group_by(State, Industry) |> slice(-(1:(n() - 12))) |> ungroup() # the last 20 rows: n() - 19:0 runs from n() - 19 up to n() aus_production |> slice(n() - 19:0)
    • filter() by condition, slice() by position. Convert the index before comparing: year(Quarter) >= 1995, not Quarter >= 1995.
    • The parentheses are the trap. 1:(n() - 12) is the first n − 12 rows. 1:n() - 12 is something else, silently, because : binds tighter than −.
    • Many series at once: group_by() the keys before slice(), and ungroup() after, or the split happens across all series together.

    Every test set you build this term starts with filter() or slice(), so check the parentheses carefully now.

    The minus sign in slice(-(1:(n() - 12))) means "everything except these positions", the same idiom as dropping columns with select(-x).

    Why n() - 19:0 gives the last 20 rows: 19:0 is the sequence 19, 18, ..., 0, and subtracting it from n() gives n - 19 up to n. Subtracting a sequence from a number keeps its length, so the result is always 20 rows.

    fpp3 also uses filter_index() for date ranges written as strings. It is a convenience; filter() with year() or yearmonth() does the same job.

    aus_retail measures Turnover, the Australian and British word for sales. In American usage, turnover usually means staff or inventory turnover, so read it as retail sales.
    13_A › Absolute and relative errors

    Measuring a miss  ·  two families

    Error measures built on differences keep the units, and those built on ratios do not.

    absolute error |y − ŷ| in the units of y: megalitres, dollars, people relative error |y − ŷ| / |y| no units: a fraction, usually read as a percentage
    • Every metric today is one of the two, averaged in some way over the errors: MAE and RMSE are differences; MAPE is a ratio; MASE is a difference divided by a reference difference.
    • The absolute value is there so misses do not cancel. A model that is 10 too high and then 10 too low has a mean error of zero and an average miss of 10. The plain mean of the errors measures bias, not size: it is the zero-mean check of residual diagnostics (Session 9).
    • Units decide what you can compare. A difference compares models on one series. A ratio, or a scaled error, compares across series measured in different things.

    Before reading any accuracy number, check whether it is a difference or a ratio; its units will tell you.

    This is the kind of calculation the final can ask for by hand: from a few observations and forecasts in a table, the errors, the absolute errors, the percentage errors, and the metrics on the next slides. The arithmetic is easy; the judgment is in matching the metric to the question.
    13_A › Scale-dependent error metrics

    Scale-dependent metrics  ·  same units as the series

    Squaring the errors penalizes a big miss much more than taking the absolute value does.

    MAE = mean( |et| ) RMSE = sqrt( mean( et² ) )
    • MAE reads as a sentence: "on average, off by 14.3 megalitres". RMSE is in the same units but weighs large misses more, so it reacts to the occasional big error.
    • They aim at different targets. A method that minimizes the MAE forecasts the median; one that minimizes the RMSE forecasts the mean. The next slide shows why, on five numbers.
    • Neither compares across series. 14 megalitres of beer and 14 dollars of retail sales are not the same miss.

    Use MAE when you want a number a manager can read. Use RMSE when a big miss hurts more than several small ones.

    On the training set these are computed from the residuals, with the NAs at the start dropped (a seasonal naive has four of them on quarterly data). On the test set, from the forecast errors. The formulas are the same; only the vector of errors changes.
    13_A › Why the median and why the mean

    Scale-dependent metrics  ·  one forecast for many possible outcomes

    Judged by MAE, the best forecast is the median of the possible outcomes; judged by RMSE, it is their mean.

    Suppose yT+h can turn out to be 1, 2, 3, 4 or 100, each with probability 1/5: a skewed forecast distribution. You must commit to one point forecast, c. Which c gives the lowest MAE, and which the lowest RMSE?

    possible y 1 2 3 4 100 each with probability 1/5 c = 3: y − c −2 −1 0 1 97 MAE 20.2 RMSE 43.4 c = 22: y − c −21 −20 −19 −18 78 MAE 31.2 RMSE 39.0
    • Absolute errors count values, not distances. Each step of c to the right adds 1 per value below it and saves 1 per value above, so the MAE is lowest where the two sides balance: the median.
    • Squared errors let far values pull. A value twice as far away costs four times as much, so the 100 drags the best c up to the mean, 22.
    • The five outcomes stand for a forecast distribution, like the skewed ones of back-transformed forecasts in prediction intervals (Session 12). MAE rewards forecasting its median; RMSE, its mean.

    Before choosing between MAE and RMSE, decide whether the forecast should be the median or the mean of what could happen.

    How the table is built: subtract c from each possible outcome to get the errors; the MAE is the mean of their absolute values, (2 + 1 + 0 + 1 + 97) / 5 = 20.2 for c = 3, and the RMSE is the square root of the mean of their squares, √((4 + 1 + 0 + 1 + 9409) / 5) = 43.4. The same arithmetic applies to a test set: a flat forecast c against five test observations 1, 2, 3, 4 and 100 gets exactly these values.

    For the curious, the two arguments are the proofs. The slope of the MAE in c is proportional to the number of values below c minus the number above it, which is zero at the median. The mean squared error has derivative −2 mean(y − c), which is zero at c = mean(y), and the square root in the RMSE does not move the minimum. The proofs are outside this course; the statements are not.
    13_A › Percentage errors

    Percentage errors  ·  no units, three cautions

    A percentage error needs a meaningful zero, and it charges more for forecasting too high.

    pt = 100 · et / yt MAPE = mean( |pt| ) same actual, y = 100: ŷ = 150 → 50% ŷ = 50 → 50% same cost same forecast, ŷ = 100: y = 50 → 100% y = 150 → 33% too high costs more
    • It is unit-free, so it compares across series. "Off by 3.3%" means the same for beer and for retail sales.
    • It fails without a meaningful zero. A yt of zero makes the ratio infinite, and values near zero make it enormous, so daily sales of a slow product cannot be judged with MAPE. Temperature in Celsius has a zero that means nothing special, so a percentage of it means nothing either.
    • It is lopsided. With e = y − ŷ, a negative error is a forecast above the actual. With positive actuals and forecasts, a forecast below the actual can never miss by more than 100%; one above it has no ceiling. This is what fpp3 means when it says MAPE penalizes negative errors more heavily.

    A model chosen by its MAPE leans toward forecasting too low, because the forecasts that were too high are the expensive ones.

    Whether MAPE is asymmetric depends on what you hold fixed. Hold the actual at 100 and forecasts of 150 and 50 both give 50%: no asymmetry. Hold the forecast at 100 and let the actual come in at 50 or 150: 100% against 33%. In forecasting the forecast is what you commit to and the actual is what arrives, so the second reading is the one that matters, and it is the one behind fpp3's warning.

    sMAPE, the "symmetric" version, is in the notebook for completeness. It is not examined. It is not symmetric either (with y = 100, forecasts of 150 and 50 give 40% and 67%), its value can be negative, and it does not fix the zero problem.
    13_A › Scaled errors

    Scaled errors  ·  no units, no zero problem

    MASE measures every error against the naive method's typical miss on the training set.

    Q = mean |yt − yt−1| on the training set (yt−m for seasonal data) qj = ej / Q a scaled error: no units MASE = mean( |qj| ) RMSSE = sqrt( mean( qj² ) )
    • The scale, Q, is the naive method's average miss on the training set: how far the series typically moves from one observation to the next (or from one season to the next).
    • MASE below 1: smaller errors, on average, than the one-step naive forecast made on the training data. It has no units, and it works on series with zeros.
    • The benchmark is the training set, not the test set. On beer, the seasonal naive model scores exactly 1 on the training set, because its own errors are the scale, and 0.94 on the test set. It did not beat itself; its test errors were simply smaller than its training ones.

    To ask whether a model beats the naive forecast, compare its MASE with the naive row of the same table. Every row shares the same scale, so the lower MASE is the lower MAE.

    MASE and RMSSE are the scaled versions of MAE and RMSE. The notebook section that defines them is new in this build; fpp3 5.8 is the reference. accuracy() returns both, and Group Assignment 2 uses them to compare the naive method against the smoothing models.

    The scale Q is always computed on the training data, even when the metric is for the test set. That is what makes MASE comparable across series and across models fitted to the same series.

    A common misreading is "a test MASE above 1 means the naive forecast would have done better on the test set". It does not follow: the naive method's own multi-step test errors are usually larger than its one-step training errors, so its test MASE is usually above 1 too. In the notebook's Google example the naive model wins the test set with a MASE of 5.67. The fair comparison is row against row.

    The four metrics  ·  side by side

    Each metric answers a different question, so choose it before you compare models.

    Use it whenUse caseWatch out
    MAEYou want an average miss anyone can read, and every unit of miss costs the same. It targets the median.A brewery's quarterly beer production, the notebook's Example 1: each megalitre over or under costs about the same, and "off by 14 megalitres a quarter" reads at once.It cannot compare series in different units or scales.
    RMSEOne big miss hurts more than several small ones. It targets the mean.Flu vaccine doses for a region: one large miss, a shortage or a pile of wasted doses, hurts far more than several small ones.One large error can dominate it. Same units as the series, like MAE.
    MAPEYou compare series in different units or scales, with a true zero and values well above it.Google and Apple stock prices, from Example 2's gafa_stock: very different price levels, a true zero, and prices far above it.Zeros and values near zero blow it up. It charges more for forecasts that are too high.
    MASEYou compare many series, including series with zeros, against the naive benchmark.Daily sales of every product in a store's catalog, each judged against the naive forecast; slow-moving products have days with no sales.Below 1 means better than the naive forecast on the training data. To beat the naive model on the test set, compare rows.
    • Choose the metric first. Decide what a bad forecast costs you, then read that metric's column in the accuracy() table. Choosing the metric after seeing the results is choosing the winner you wanted.
    • When the metrics agree, the choice does not matter, as on beer, where the seasonal naive wins every column. When they disagree, the metric you chose first decides.
    • Report each number with its unit: MAE and RMSE in the units of the series, MAPE in percent, MASE in none.
    Every row of the table comes from the four slides before it: the median and the mean from the median-or-mean slide, the cost of forecasts that are too high from the percentage-errors slide, and the reading of MASE from the scaled-errors slide. The use cases are examples, not rules: the same series can call for a different metric when the cost of a miss is different.

    A second reason to choose RMSE is forecasts that will be added up, such as regional sales summed to a national total: the sum of the means is the mean of the sum, but the sum of the medians is not the median of the sum. Prediction intervals (Session 12) made the same point about back-transformed forecasts.

    Now we compute  ·  beer, four benchmarks, 1992 to 2007 for training

    accuracy() on the models gives residual metrics; on the forecasts, with the full data, it gives forecast errors.

    beer_fit |> accuracy() # .type = Training: from the residuals beer_fc |> accuracy(recent_production) # .type = Test: forecasts matched to the full series

    Mean35.2 · 43.6 · 7.9% · 2.4634.8 · 38.4 · 8.3% · 2.44

    • Two calls give two tables. On the mable, accuracy() reads the residuals. On the fable, it needs the whole series to match each forecast with the observation it missed.
    • Read the units. MAE and RMSE in megalitres; MAPE in percent; MASE against the seasonal naive's training miss, which is why its own training MASE is 1.
    • Here the seasonal naive wins on both sets, on every metric. Usually one model wins on one metric and another on another; then you choose the metric before you choose the model.

    The notebook's Google example applies the same workflow to non-seasonal data. The code is the same, but a different model wins.

    Why the naive and the drift methods tie on the training set: their fitted values differ by one constant, the estimated slope, so their residuals differ by that constant too and the absolute and squared averages barely move. On the test set the drift's slope carries the forecast away from the seasonal pattern and it loses by a little.

    The training MAPE of 3.3% for the seasonal naive reads as: on average, last year's same quarter was 3.3% away from this year's.
    13_A › Manual computation of MAE and RMSE

    Now we compute  ·  drift model, both sets

    Four lines reproduce accuracy(), and a fifth, all.equal(), checks that they match.

    # training set: the residuals resid <- beer_fit |> select(Drift) |> augment() |> pull(.innov) |> na.omit() MAE_manual <- mean(abs(resid)); RMSE_manual <- sqrt(mean(resid^2)) # test set: observations minus forecasts fc <- beer_fc |> filter(.model == "Drift") |> pull(.mean) tv <- recent_production |> filter(Quarter >= yearquarter("2008 Q1")) |> pull(Beer) err <- tv - fc all.equal(sqrt(mean(err^2)), RMSE_fable) # TRUE
    • Residuals come out of augment(); drop the NAs before averaging, or the metric is NA.
    • Forecast errors are observations minus forecasts, in that order, matched quarter by quarter. The sign convention matters for the mean error; it vanishes under the absolute value and the square.
    • The homework repeats this for the seasonal naive. It uses the same four lines with a different model name, and there are four NAs to drop instead of one.

    If you can do this with a calculator on a table of ten numbers, you can check every number accuracy() reports.

    Model names with spaces, such as Seasonal naive, need backticks when used in select(). Or name the models without spaces when you fit them.

    Why accuracy() wants the full series rather than the test set alone: it matches each forecast to the observation at the same index, and it needs the training part to compute the scale for MASE. Passing only the test set gives the same MAE and RMSE and a different MASE.
