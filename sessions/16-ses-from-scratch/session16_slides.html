    16_D › The outline

    Session 15's flowchart  ·  with a function name on each box

    The plan has four boxes: three functions that you write and one searcher from base R.

    • ses_levels() is the level column: given α, ℓ0 and the series, run the recursion and return every level.
    • SSE_func() is the squared-errors column: given the series and the fitted values, return one number.
    • my_ses_sse() glues them together in the shape optim() expects: one vector of parameters in, one number out. optim() does steps 1 and 4: guess, evaluate, adjust, repeat.

    You write the part that knows about time series. optim() writes the part that knows about searching. Neither needs to understand the other.

    The notebook provides templates for all three functions with the gaps marked TODO, and a test after each one. Complete them in order; each test tells you whether the previous function is right before you build on it.

    optim() lives in the stats package, which R loads at start-up. Nothing to install.
    16_D › 1. Function ses_levels

    Now we code  ·  function 1 of 3

    One vector holds every level: the fitted values first, the forecast last.

    ses_levels <- function(y, alpha, l_0) { levels <- numeric(length(y) + 1) # T + 1 slots, from t = 0 to t = T levels[1] <- # TODO # the level at t = 0 for (i in 2:length(levels)) { levels[i] <- # TODO # the smoothing equation } levels }
    • Position i holds time i − 1, because the vector starts at ℓ0. That is why the loop runs from 2 and reads y[i-1]: position 2 is time 1, and time 1's level uses observation 1.
    • Why return all T + 1 levels and not just the fitted values: the last one is the forecast, and SES forecasts are flat, so that one number is every forecast.
    • Fill the two TODO lines now. The next slide tests them.

    The inherited notebook called this function levels, which hides a base R function of the same name. It is ses_levels now.

    The index shift is the only hard thing in this function. A way to keep it straight: write the vector on paper with two rows of labels, positions above and times below, and read the smoothing equation off the paper. The slide does that for you.

    Why numeric(length(y) + 1) before the loop: allocating the full vector once and filling it is both clearer and faster than growing it one element at a time.

    16_D › 3. Function my_ses_sse

    Now we code  ·  function 3 of 3

    optim() talks to one function with one vector of parameters, so wrap yours to match.

    my_ses_sse <- function(par, y) { alpha <- par[1] # unwrap the parameter vector l_0 <- par[2] T <- # TODO # the length of the series levels_values <- # TODO # the levels, given y, alpha and l_0 yhat_fvals <- # TODO # the fitted values, from the levels SSE <- # TODO # the SSE, given y and yhat_fvals SSE } all.equal(1995.285, round(my_ses_sse(c(alpha, l_0), y), 3)) # TRUE
    • Nothing new is computed. The wrapper unwraps par, calls the two functions and returns the SSE, so it is pure composition.
    • Why the parameters travel in one vector: optim() adjusts a vector of numbers and nothing else. α and ℓ0 ride together in par; the series rides separately, as a further argument.
    • The signature is the contract: f(par, ...) in, one number out. Any function shaped like that can be minimized by optim(), whatever it computes.

    All three functions return TRUE, so the model is written and only the search remains.

    The order inside par is a convention you choose and then must keep: here par[1] is α and par[2] is ℓ0, so the starting guesses and the output of optim() follow the same order.

    Holt's method in Session 17 would use a par of four: α, β*, ℓ0, b0. Same wrapper, longer vector.
    16_D › 4. Understanding optim()

    The searcher  ·  no formula, only steps

    optim() walks downhill on the SSE until it cannot go lower.

    • The fog analogy. You stand on a hillside in fog and want the lowest point. You cannot see it, but you can feel the slope, so you step downhill, and again, until every direction goes up.
    • Two consequences, both on the final as concepts: where you start matters, because a different valley is possible; and the answer is approximate, because "flat enough" is a judgment the algorithm makes.
    • The real search is in two dimensions, α and ℓ0 together. The picture shows one for clarity; optim() does not care how many.

    A model "fitted by minimizing the SSE" was fitted by a walk like this. Session 19 changes what is walked on, not the walking.

    The starting guesses in the notebook: α = 0.1, a method that takes the past into account, and ℓ0 = y1, because the first observation is a good guess for the first level. The notebook explains both; they are reasonable, not unique.

    How optim() feels the slope with no formula: it evaluates the function at nearby points and compares. The default method is Nelder–Mead, which needs no derivatives. The details are outside this course.

    Algerian exports  ·  the four fields of an optim() result

    Three decimals of agreement is a match, and the rest comes from the starting point and the algorithm.

    opt <- optim(par = c(0.1, algerian_exports$Exports[1]), fn = my_ses_sse, y = algerian_exports$Exports) $par 0.8399 39.53 # alpha, then l_0: the order we chose for par $value 1995.285 # the SSE at the end of the search $counts 53 # evaluations of my_ses_sse on the way down $convergence 0 # 0 means it stopped because it was flat, not because it gave up tidy(fit) |> pull(estimate) # fable: 0.8400 39.54
    • par is the answer, in the order you defined. value is the SSE there. counts says how many steps the walk took. convergence of 0 is the only good value.
    • fable says 0.8400 and 39.54. The difference is in the fourth decimal: a different starting point and a different algorithm reach almost, not exactly, the same bottom of the same valley.
    • This is the expected result, and the notebook explains why; an exact match would be surprising.

    You have reproduced what ETS() does, with fifteen lines of your own. Keep them; Session 17 only adds lines.

    Why fable and optim() differ at all: fable starts the search from its own heuristic initial values and uses its own optimizer with its own stopping rule. On a smooth bowl like this one they agree to three decimals; on a bumpier surface, with more parameters, they could land in different valleys, which is one reason Session 19 looks at more than the SSE.
    16_D › 5. Fitting SES to Argentinian exports

    Now we compute  ·  a new series, the same fifteen lines

    Fitting a new series takes no extra work, because the functions do not know which series they are on.

    arg_exports <- global_economy |> filter(Country == "Argentina") |> select(Year, Exports) opt <- optim(par = c(0.1, arg_exports$Exports[1]), fn = my_ses_sse, y = arg_exports$Exports) opt$par # 0.886 7.41 fit <- arg_exports |> model(ETS(Exports ~ error("A") + trend("N") + season("N"))) tidy(fit) |> pull(estimate) # 0.886 7.41 all.equal(tidy(fit) |> pull(estimate), opt$par) # a small relative difference, as expected
    • α = 0.89: Argentinian exports are jumpy too, so the forecast leans almost entirely on the last observation.
    • ℓ0 = 7.41, close to the first observation, as the starting guess assumed.
    • all.equal() reports a tiny difference rather than TRUE. This is the main result of Session 16: the fit comes from a numerical search rather than a formula, so two searches agree closely but not exactly.
